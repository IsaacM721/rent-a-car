Backend: Where does the real-time magic live?

This powers GPS tracking, ride matching, driver availability, and the 5% cut logic.

A

Firebase (Google)

The industry standard for ride-hailing MVPs. Real-time database, auth, push notifications, and cloud functions all in one. Scales automatically. Most Uber clones are built on this.

✓ Real-time GPS out of the box  ·  ✓ Free tier is generous  ·  ✓ SwiftUI SDK is excellent

B

Supabase + PostgreSQL

Open-source Firebase alternative. Real-time subscriptions, Postgres database, auth. You own your data. Good Swift SDK.

✓ You own the data  ·  ✓ SQL = easier reporting  ·  ⚠ Real-time less battle-tested than Firebase

C

Laravel API (your existing stack)

Build a custom backend with the Laravel skills you already have from motores.rd. Full control, WebSockets via Reverb, connect to MySQL.

✓ You know this stack  ·  ⚠ More work to build real-time GPS  ·  ⚠ Slowest to launch

My recommendation: A — Firebase. Real-time driver location on a map is the hardest part of this app. Firebase Realtime Database was literally built for this use case. You'll be live in weeks, not months.
